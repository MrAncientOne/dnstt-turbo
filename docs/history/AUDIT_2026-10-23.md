# dnstt-turbo audit — 23 October 2026

**Follow-up:** all five findings now have production fixes and promoted
regression tests in build `2026-10-24-auditfix1`. See the
[fix and validation report](FIXES_2026-10-24.md). The rest of this document
records the original audited snapshot and its results.

Five defects were reproduced in the current source. The existing suite passed
all nine packages normally and under the race detector; the new assertions
expose gaps that those passing tests did not cover. Production source, existing
tests, dependencies and distributed binaries were not changed by this audit.

## Scope and official baseline

The checkout's sole grafted commit is `89d242c`, with `origin` pointing to
`https://github.com/gh4rib/dnstt.git`. That remote is a fork, not the official
comparison source. This audit includes the current staged, unstaged and
untracked production files, rather than reviewing only committed history.

The official reference is release **v1.20260501.0**, commit
`0c5c52a57d899c05428c116898941761a2ed83c2`, obtained from the
[Go module proxy](https://proxy.golang.org/www.bamsoftware.com/git/dnstt.git/@v/v1.20260501.0.info).
The proxy's `@latest` resolved to this release during the audit. Direct access
to the primary Git endpoint stalled/failed, and its mirror failed TLS; no claim
is made about untagged official branch-tip changes after this release.

An immutable source snapshot, SHA-256 inventory, official zip/hash, file drift
inventory and full Go source diff are retained in
`/workspace/dnstt-audit/audit-20261023/`. The portable tests and release metadata
are also saved under [tests/audit/20261023](../../tests/audit/20261023/README.md).

Compared with the 29 files in the official release, 16 differ, 13 are identical,
and none are removed. Added files include tests and documentation as well as
production code. Important behavioral changes are:

| Area | Drift from the official release |
| --- | --- |
| Carrier | Adds direct DNS-over-TCP and an optional private EDNS upload option; official supports UDP, DoH and DoT. Both turbo endpoints are needed for the new carrier. |
| Windows and queues | Makes KCP/poll/smux limits configurable, raises the default server KCP window to 65535, and sizes packet queues from that ceiling. |
| Adaptation and scheduling | Adds independent directional feedback, BBR-lite, upload pacing and optional fair upload/download scheduling. |
| Recovery | Adds transport/session rebuilds, bounded handshakes and framed TCP operations, cancellation and worker cleanup. |
| Noise | Keeps the NK handshake/prologue and cipher suite; adds write serialization. This is not a replacement cryptographic protocol. |
| Diagnostics | Adds rate files, health counters, rotating logs and test fixtures. |
| Dependencies | `go.mod` and `go.sum` are byte-identical to this official release, including old uTLS/x/net versions. |

The official May 2026 send-error and top-level loop-exit reliability fixes are
present in turbo's `sendLoop` and `run`; the fork's older CHANGELOG does not
describe them. An old changelog is not evidence that the actual fix is absent.

## Standards

No repository-specific standards document or originating issue tracker was
found. These are concrete behavior/resource defects rather than style-smell
judgments. Full independent analysis and commands are in
[standards.md](../../tests/audit/20261023/standards.md).

### 1. P1 — unauthenticated empty polls allocate about 3 MiB per client ID

Locations: [default window](../../dnstt-server/main.go#L101),
[queue sizing](../../dnstt-server/main.go#L1253),
[per-query lookup](../../dnstt-server/main.go#L854), and
[remote-record allocation](../../turbotunnel/remotemap.go#L138).

An otherwise valid empty query carrying an arbitrary new eight-byte ClientID
creates a 131070-entry slice channel at the default server window. No KCP
payload or Noise handshake is required. Eight wire queries through the actual
receive/send path retain **25,169,392 bytes** in one packaged run, versus
**36,512 bytes** in the official control. The incoming queue's initial
allocation is excluded from that measurement.

The 32-TCP-connection cap does not cap IDs supplied on one carrier. Remote
records expire after minutes, so they accumulate long enough to exhaust server
memory. Large default queue allocation also makes legitimate client churn more
expensive. The test bounds its workload to eight IDs; no exhaustion attack was
performed. Fix direction: bound unauthenticated state and avoid allocating the
maximum negotiated data window eagerly for every query ID.

### 2. P2 — one TCP client can block replies to unrelated clients

Locations: [global response writer](../../dnstt-server/main.go#L945) and
[framed write](../../dnstt-server/tcp.go#L203).

The single global send loop synchronously calls `WriteTo`. Once a client's
outbound socket buffer fills because it stops reading, all later clients'
responses wait behind that write, potentially until its 30-second deadline.
The minimized test uses actual transport connections backed by `net.Pipe` to
model an already-full buffer. A healthy peer gets no response within 100 ms;
releasing the stalled peer unblocks the loop. This does not imply one small
response fills a real kernel buffer. Repeated responses are needed there.

Official dnstt has no equivalent TCP listener. Fix direction: isolate bounded
per-connection output/backpressure while preserving ordering and cancellation.

### 3. P2 — accepting a smaller EDNS limit can make data unrecoverable

Locations: [query admission](../../dnstt-server/main.go#L629),
[listener MTU](../../dnstt-server/main.go#L1073), and
[response truncation](../../dnstt-server/main.go#L934).

With listener response cap 16384, KCP is configured for 1400-byte segments.
An accepted query advertising 1232 or 512 bytes can receive a 1478-byte response
that is sliced to its advertised cap with TC set. The actual DNS parser returns
`unexpected EOF`. Retransmitting the same segment cannot correct the size
mismatch. Small handshake/control packets can succeed before bulk data stalls.

The 4096-byte control passes. Official's default 1232-byte configuration uses
KCP MTU 932 and passes the corresponding control. This affects the documented
mixed-size recipe; the direct TCP client advertising 65535 is unaffected.
Using separate `-mtu 1232 -tcp-mtu 16384` listeners avoids the demonstrated
1232-byte case. General support needs a segment size that fits each accepted
client, or explicit rejection of unsupported sizes; raw byte truncation cannot
provide that negotiation.

## Spec

The behavior contract is TURBO_README.md plus the documented controller and

[spec.md](../../tests/audit/20261023/spec.md).

### 4. P2 — live rate updates erase admission-shaper debt

Locations: [shaper replacement](../../fairqueue/fairqueue.go#L318) and
[periodic rate update](../../dnstt-client/main.go#L427).

The documented slow-path admission protection is defeated when `SetRate`
replaces the whole shaper every 100 ms, including when its rate is unchanged.
One test observes a pending four-second wait becoming zero. A live scheduler
test admits its second 4096-byte chunk immediately after reapplying 1024 B/s.
This can increase buffering and interactive delay. The separate carrier pacer
still operates; this is not a complete bypass of all tunnel pacing.

A diagnostic overlay preserving the clocks passes both new assertions and
existing static shaping coverage, three repetitions under `-race`. That
establishes causality; the overlay is not a reviewed production fix. Fix
direction: preserve/rebase outstanding debt when rates change. Requires
`-bbr` and `-fair-upload` in the production client.

### 5. P2 — small valid segments undersize the adaptive receive window

Location: [observed segment threshold](../../dnstt-client/adaptive.go#L63).

Supported server `-kcp-mtu-cap 200` yields 176-byte KCP payloads. The adaptive
code ignores observations below 256 and retains its initial 1376-byte model.
Actual feedback-to-controller tests therefore advertise only **45,056 actual
flight bytes** where the measured workload calls for **352,000 bytes** under
the controller's own two-horizon target. The normal-size control passes.

An isolated observed-size counterfactual passes the new test and all existing
adaptive tests, three repetitions under `-race`. This demonstrates incorrect
flight sizing, not a measured WAN throughput ratio. Fix direction: use the
observed supported payload size instead of discarding it. Requires `-bbr` and
a sufficiently small downstream segment configuration.

## Inherited dependency risks

`govulncheck v1.9.0`, Go 1.27.2, queried the Go vulnerability database dated
2026-10-21 for both source trees. Raw JSON is retained as `govulncheck.json` and
`govulncheck-official.json`; compact fork results are in
`vulnerability-summary.json` under the audit directory.
Both trees produced the same 14 advisory IDs with symbol-level traces; the
comparison is saved in `dependency-comparison.json`. That count is scanner
output, not 14 independently demonstrated exploitable vulnerabilities.

Directly relevant alerts include uTLS 1.6.6's missing downgrade checks
([GO-2025-3638](https://pkg.go.dev/vuln/GO-2025-3638)) and Chrome fingerprint
differences ([GO-2026-4509](https://pkg.go.dev/vuln/GO-2026-4509),
[GO-2026-4512](https://pkg.go.dev/vuln/GO-2026-4512)). The advisory fixed versions
are respectively 1.7.0, 1.8.1 and 1.8.2. The pinned x/net also predates the
HTTP/2 transport fix for malformed SETTINGS_MAX_FRAME_SIZE
([GO-2026-4918](https://pkg.go.dev/vuln/GO-2026-4918)). These are inherited
dependency risks in the DoH/DoT paths, not regressions created by turbo's plain
TCP carrier. A dependency update needs TLS fingerprint/compatibility checks.

Other scanner reports include broad CIRCL package advisories without reviewed
symbol attribution and HTTP server/unused SSH paths. A static call trace is
not an exploit demonstration; this audit does not classify every scanner
match as an applicable vulnerability. No live vulnerability exploitation was
performed, and plain `-tcp` does not exercise uTLS/DoH.

Real-process tests were stopped after the control failure; the later finite
transfer and half-close scenarios were not reached. Earlier synthetic uplink
results remain useful but do not replace these missing deployment checks.
Supplemental concurrent buffer-clamp stress did not produce a race in natural
handshakes; it is not included among confirmed findings.

Run the packaged probes with:

```sh
python3 tests/audit/20261023/run.py --race --repeat 3
```

Exit status 1 is intentional on the audited source. The regression fixtures
are injected using overlays and do not make the normal suite fail. Production
files should be fixed and the appropriate assertions promoted into their
packages in a follow-up change. None of these results establishes that a new
fork defect caused the user's current static-mode Codex/DNS delay.

Standards: three findings, worst is unauthenticated memory amplification.
Spec: two findings, both affect optional adaptive behavior.
